# Sysmon lab capture on SYN-DRV-W11

This procedure is for the Windows 11 VM `SYN-DRV-W11` only. Sysmon installs a Windows service and a boot-start kernel driver. Do not install it on the Windows host running the VM. Take a VM snapshot first and keep the VM's lab network restrictions in place.

The sample config is [sysmon-adr0026.xml](sysmon-adr0026.xml). It enables only the filterable IDs from ADR-0026's allowlist: 2, 9, 15, 17, 18, 23, 25, and 26. IDs 4, 16, and 255 are not filterable by Sysmon's event filters and are generated by Sysmon itself. In Sysmon an event type with `onmatch="exclude"` and no rule logs everything, while `onmatch="include"` with no rule logs nothing, so the file uses `exclude` for the event types that should be captured whole. Event 23 is the exception: it archives every deleted file it logs, so it is limited to deletions under `C:\Lab\SysmonDeleteTest\`, and event 26 (same deletions, no archive) covers the rest. This config changes Sysmon event selection only; it does not change Defender, the firewall, audit policy, or other protections.

## Install on the VM

1. Open an elevated PowerShell **inside `SYN-DRV-W11`**. Check for an existing Sysmon service or channel before installing; do not overwrite a pre-existing or Windows-native Sysmon installation.

   ```powershell
   Get-Service -Name '*Sysmon*' -ErrorAction SilentlyContinue
   Get-WinEvent -ListLog '*Sysmon*' -ErrorAction SilentlyContinue |
       Format-Table LogName, IsEnabled, RecordCount
   ```

2. Download the current Sysinternals Sysmon package from [Microsoft Sysinternals](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon) or its official [Sysmon.zip](https://download.sysinternals.com/files/Sysmon.zip) link. Extract it in the VM, for example to `C:\Lab\Sysmon`. Copy `sysmon-adr0026.xml` into that directory.

3. Confirm the package's config schema before installing. The checked-in XML uses schema 4.90; if the downloaded binary reports another schema or rejects the file, use that binary's `-s` output and adjust only the `schemaversion` before installation.

   ```powershell
   Set-Location C:\Lab\Sysmon
   .\Sysmon64.exe -s
   [xml](Get-Content -Raw .\sysmon-adr0026.xml) | Out-Null
   ```

4. Install with the allowlist config from the elevated VM PowerShell:

   ```powershell
   .\Sysmon64.exe -accepteula -i .\sysmon-adr0026.xml
   ```

   Event 23 (`FileDelete`) archives the contents of the files it logs under Sysmon's archive directory. The sample config limits it to `C:\Lab\SysmonDeleteTest\`: create that folder, and delete a file in it during the capture to get a sample of event 23. Watch free space anyway, and do not delete archived evidence before Nikolas confirms it is no longer needed.

   After installing, check that the filters took effect: `.\Sysmon64.exe -c` prints the active configuration, and the events of types 2, 9, 15, 17, 18, 25 and 26 should appear in the channel within a few minutes of ordinary use (17 and 18 within seconds). If an event type stays absent, say so in the capture report; do not conclude that Windows does not emit it.

## Verify the channel and capture

Check that the Sysmon log exists and is enabled, then inspect the newest records:

```powershell
Get-WinEvent -ListLog '*Sysmon*' |
    Format-Table LogName, IsEnabled, RecordCount, MaximumSizeInBytes

Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' -MaxEvents 20 |
    Select-Object TimeCreated, Id, ProviderName, Message
```

For a focused query, including service/configuration events when present:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-Sysmon/Operational'
    Id = @(4, 16, 255)
    StartTime = (Get-Date).AddHours(-2)
} -MaxEvents 100 | Select-Object TimeCreated, Id, Message
```

From the repository root inside the VM, run the existing lab capture as Administrator **without** `-SkipSysmon`:

```powershell
.\lab\capture-sysmon-etw.ps1 `
    -OutDir 'C:\Lab\Captures\sysmon-20261007' `
    -IdleSeconds 60 -BusySeconds 60 -SysmonSample 5000
```

Let both phases finish. Send the entire output directory to Nikolas: `summary.txt`, raw Sysmon XML sample(s), ETL files, and any other files written there. Keep the ETLs; they are needed to re-check provider data and loss counters.

Export the complete retained Sysmon channel as EVTX as well. `wevtutil epl` exports the event log records without converting them to rendered text or a filtered sample:

```powershell
wevtutil.exe epl 'Microsoft-Windows-Sysmon/Operational' `
    'C:\Lab\Captures\sysmon-20261007\sysmon-operational.evtx' /ow:true
```

Include `sysmon-operational.evtx` in the folder sent back. Run the export before uninstalling Sysmon or clearing any event log.

## Uninstall after the capture

After Nikolas confirms the export and output folder were collected, uninstall from elevated PowerShell **inside the VM**:

```powershell
Set-Location C:\Lab\Sysmon
.\Sysmon64.exe -u
```

Microsoft documents `-u` as uninstalling the Sysmon service and driver; a reboot is not required. This does not delete the files created for this lab: the downloaded ZIP and executable, config XML, capture folder, EVTX export, or any Event 23 archive. Keep those until the results are accepted, then remove only the lab artifacts you created. The uninstall documentation does not promise to erase the Operational channel's existing records, so export first and inspect the channel afterward rather than assuming it was cleared.
